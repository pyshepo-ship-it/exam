### 💻 الاختبارات الإلكترونية — من يستطيع فتحها؟
من **الاختبارات ← لوحة تحكم الاختبار** (أو من نموذج إنشاء/تعديل الاختبار) تختار:

- **للأعضاء المسجلين فقط** (الافتراضي):
  - يظهر الاختبار للطالب في بوابته **حسب صفه** (ومجموعاته المستهدفة إن حدّدتها — اتركها فارغة ليظهر لكل مجموعات الصف)
  - عند البدء **تظهر بيانات الطالب تلقائياً** من حسابه (الاسم + الصف + المجموعة) ولا يملأ أي بيانات — يجيب عن الأسئلة فقط
  - غير المسجَّل يرى بوابة تسجيل الدخول/إنشاء حساب، ويعود للاختبار تلقائياً بعد الدخول
  - درجته تُربط بحسابه وتظهر في تقريره

- **مفتوح لأي أحد بدون تسجيل**:
  - يظهر في **لوحة الإعلانات** (الصفحة الرئيسية) مع شارة «بدون تسجيل»، ويمكنك أيضاً **نسخ رابطه** ونشره مباشرة
  - الزائر يُدخل **اسمه ورقم هاتفه** (إجباريان)، و**الصف ثابت** من إعداد الاختبار (محدد مسبقاً — لا يستطيع تغييره)
  - يختار **مجموعته من قائمة منسدلة** تعرض مجموعات صفه المتاحة لهذا الاختبار فقط
  - بعد تعبئة بياناته يُفتح له زر «بدء الاختبار»
  - محاولته تصلك في **نتائج الاختبار** باسمه ورقم هاتفه ومجموعته مع شارة «زائر — بلا حساب»
  - الطالب المسجَّل الدخول الذي يفتح اختباراً مفتوحاً للجميع لا يُطلب منه شيء: هويته تلقائية كالأعضاء

> إعدادات مشتركة للوضعين: الإتاحة الزمنية (دائماً/فترة محددة)، حد عدد مرات الاجتياز (يسري على الزائر أيضاً عبر الأجهزة)، إظهار الإجابة الصحيحة، ولوحة الشرف التلقائية.

> ☁️ لمشروع قائم على Supabase: شغّل `supabase/migrations/013_exam_access_mode.sql` مرة واحدة ليُضاف عمود رقم هاتف الزائر إلى `exam_attempts` (التطبيق يعمل بدونه أيضاً ويتجاهل الهاتف حتى تشغيله).

### 📢 الإعلانات ولوحة الشرف (الصفحة الرئيسية)
- الصفحة الرئيسية للموقع أصبحت عامة وتعرض: الإعلانات، لوحة الشرف، ملفات للتحميل، وروابط مهمة
- تسجيل الدخول أصبح من صفحة `/login` (زر "تسجيل الدخول" في أعلى الصفحة الرئيسية)
- **الإعلانات**: إعلانات مهمة مع إمكانية التثبيت في الأعلى
- **لوحة الشرف**: تثبيت اسم طالب (أو أكثر) في مجموعته لمدة شهر كـ"المتميز في الامتحان هذا الشهر"
- **ملفات للتحميل**: رفع ملفات (حتى 2 ميجا) أو روابط خارجية
- **روابط مهمة**: روابط للطلاب تظهر على الصفحة الرئيسية

### ☁️ التخزين: Supabase فقط — صفر تخزين محلي
- **Supabase هو المكان الوحيد الذي تُسجَّل فيه البيانات**: الطلاب، الصفوف، المجموعات، المواعيد والحصص،
  الحضور، الاستحقاقات والمدفوعات، الاختبارات ومحاولاتها ونتائجها، الإعلانات، لوحة الشرف، الملفات
  والروابط، الاستفسارات، طلبات التسجيل والنقل، سجل الطالب، أرشيف السنوات، والإعدادات كلها.
- **الجلب تلقائي من السحابة**: كل صفحة تجلب بياناتها من Supabase عند فتحها، ولوحة التحكم تسحب كل
  الجداول (`pullAllData`) قبل أن تعرض أي شيء — فتجد بياناتك محدَّثة دائماً.
- **من أي جهاز وأي مكان في العالم**: الطالب يفتح اختباره أو حسابه، وصاحب الموقع يفتح لوحته،
  فيجدان نفس البيانات المحدَّثة — لأنه لا توجد نسخة محلية على أي جهاز.
- **لا يُكتب أي بيان في المتصفح إطلاقاً** (لا `localStorage` ولا `sessionStorage` ولا `IndexedDB`).
  أثناء التصفّح تعمل ذاكرة جلسة مؤقتة (داخل التبويب) تُعبَّأ من Supabase وتُمسح عند تحديث الصفحة
  أو إغلاقها أو تسجيل الخروج.
- **أي كاش قديم تركته إصدارات سابقة في المتصفح** يُنقل تلقائياً إلى الذاكرة (ليرفع إلى السحابة إن
  كانت فارغة) ثم **يُمسح من الجهاز نهائياً** عند أول إقلاع.
- ما يبقى على الجهاز وليس بيانات إطلاقاً: كوكي جلسة دخول الطالب (30 يوماً، بلا كلمة مرور)،
  مظهر الموقع (ليلي/نهاري)، وعدّاد حماية الإغراق (أرقام فقط — يمنع تكرار طلبات التسجيل).
- بدون ضبط متغيرات Supabase لا يُحفظ أي بيان: تظهر رسالة «غير متصل بـ Supabase — لا يُحفظ أي بيان».
- **الحارس الآلي**: `scripts/cloud-only-audit.mjs` يفحص كل `src` ويُفشل الالتزام إذا ظهر أي تخزين
  محلي للبيانات من جديد (20/20 فحصاً داخل `npm run verify`).

## 🚀 الإعداد والتشغيل

### المتطلبات الأساسية

- Node.js 22 أو أحدث
- npm أو yarn
- حساب Supabase (مجاني)
- حساب Vercel (مجاني)

### 1️⃣ تثبيت المكتبات

```bash
npm install
```

### 2️⃣ إعداد Supabase

راجع ملف [SUPABASE_SETUP.md](./SUPABASE_SETUP.md) للتعليمات الكاملة.

**ملخص سريع:**

1. أنشئ مشروع Supabase جديد
2. أنشئ حساب مستخدم في Authentication
3. شغّل ملف `supabase/schema.sql` في SQL Editor
4. انسخ مفاتيح API

### 3️⃣ إعداد المتغيرات البيئية

أنشئ ملف `.env.local` في جذر المشروع:

```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

### 4️⃣ التشغيل المحلي

```bash
npm run dev
```

افتح [http://localhost:3000](http://localhost:3000)

### 5️⃣ النشر على Vercel

1. ارفع الكود إلى GitHub
2. اذهب إلى [vercel.com](https://vercel.com) وسجّل الدخول بحساب GitHub
3. اضغط **Add New → Project** واختر repository الخاص بك
4. Vercel يتعرّف على المشروع تلقائياً (Next.js):
   - **Framework Preset**: Next.js
   - **Build Command**: `npm run build`
   - **Output Directory**: `.next` (الافتراضي)
5. قبل الضغط على Deploy، افتح **Environment Variables** وأضف:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGc...
```

6. اضغط **Deploy**

بعد أول deploy، كل push على الفرع الرئيسي ينشر تلقائياً، وكل Pull Request يحصل على رابط معاينة (Preview).

راجع [vercel.json](./vercel.json) للإعدادات (إطار العمل وأوامر البناء وترويسات الأمان).

> **ملاحظة**: المشروع لم يعد يستخدم Netlify — تم حذف `netlify.toml` وإزالة حزمة `@netlify/plugin-nextjs`.

## 🔒 الأمان

### ✅ ما تم تأمينه:

- **لا توجد بيانات حساسة في الكود**
  - اسم المستخدم وكلمة المرور في Supabase فقط
  - المفاتيح في المتغيرات البيئية
  
- **Row Level Security (RLS)**
  - جميع الجداول محمية بـ RLS
  - فقط المستخدمون المصادق عليهم يمكنهم الوصول
  
- **HTTPS**
  - Vercel يوفر HTTPS تلقائياً
  - جميع الاتصالات مشفرة

- **Environment Variables**
  - المفاتيح ليست في Git
  - محمية في Vercel Dashboard

## 📖 الاستخدام

### الصفحة الرئيسية وتسجيل الدخول

الصفحة الرئيسية `/` هي لوحة الإعلانات ولوحة الشرف العامة (لا تحتاج تسجيل دخول).
للوصول إلى لوحة التحكم اضغط زر "تسجيل الدخول" في أعلى الصفحة وستنتقل إلى `/login`
(استخدم البريد الإلكتروني وكلمة المرور اللذين أنشأتهما في Supabase).

### إضافة البيانات

1. **الصفوف**: أضف الصفوف والمجموعات مع الجداول
2. **الطلاب**: سجل الطلاب واربطهم بالمجموعات
3. **التحصيل**: أنشئ استحقاقات وسجل المدفوعات
4. **الاختبارات**: أنشئ اختبارات وصدّرها PDF
5. **الحضور**: سجل الحضور اليومي

### النسخ الاحتياطي

اذهب إلى **الإعدادات** → **تصدير البيانات** لحفظ نسخة احتياطية.
