# 🎓 نظام إدارة الدروس الخصوصية

نظام متكامل لإدارة الدروس الخصوصية والطلاب والتحصيل المالي والاختبارات.

## ✨ المميزات

### 📚 الصفوف والمواعيد
- إدارة الصفوف الدراسية
- إنشاء مجموعات مع جداول زمنية
- **طريقتان لتسعير المجموعة** عند الإنشاء/التعديل:
  - **سعر شهري** ثابت
  - **سعر للحصة × عدد الحصص في الشهر** — وعدد الحصص يُحسب تلقائياً من أيام المجموعة (اليوم الواحد ≈ 4.33 حصة شهرياً) ويمكن تعديله يدوياً
  - يُشتق السعر الشهري الفعلي وسعر الأسبوع تلقائياً من أيٍّ من الطريقتين، فتتفق كل الشاشات (المجموعات، التحصيل، التقارير) على رقم واحد
- عرض الجدول الأسبوعي للحصص

### 👥 الطلاب
- تسجيل الطلاب وربطهم بالمجموعات
- كشف حساب مفصل لكل طالب
- تصدير كشوف الحسابات إلى PDF

### 💰 التحصيل والاستحقاقات
- إدارة المستحقات والمدفوعات
- **دورات استحقاق متعددة** عند الإنشاء: **شهري** أو **أسبوعي** (أسبوع السبت ← الجمعة، مع أزرار هذا الأسبوع/الماضي/القادم) أو **بالحصّة** (تاريخ + عدد الحصص) أو **مبلغ مخصص** بوصف حر
- **مبلغ يدوي** يتجاوز سعر المجموعة لأي دورة، مع خيار استخدام سعر المجموعة
- إنشاء جماعي: للجميع أو لصف/مجموعة محددة أو لطالب واحد، مع **منع التكرار** لنفس الفترة (مفتاح الفترة `period_key`)
- كل دفعة يمكن **ربطها باستحقاق محدد**: تُحدَّث حالته تلقائياً إلى مدفوع/جزئي ويُحسب المتبقي
- **كشف الحساب مرتّب حسب فترات الاستحقاق** (لا الشهر فقط) في صفحة التحصيل وفي تقرير الطالب المطبوع، مع شارة نوع الدورة لكل فترة
- تتبع الأرصدة والمتأخرات

### 📝 الاختبارات
- عند الضغط على **«إنشاء اختبار جديد»** تختار أولاً واحداً من خيارين فقط:
  - **اختبار ورقي**: الورقة المعتادة التي تكتبها ثم تعاينها وتطبعها أو تحمّلها PDF.
  - **اختبار إلكتروني**: يؤديه الطلاب من بوابة الموقع؛ ثم تختار نمطه: **اختياري وصح وخطأ** (تصحيح تلقائي)، أو **مقالي** (تصحيح يدوي)، أو **مختلط**.
- محرر كامل الصفحة للاختبار مع حفظ تلقائي يحمي التعديلات عند الرجوع غير المقصود.
- في المقالي والمختلط يراجع المعلم كل إجابة: كامل/نصف/صفر أو درجة مخصصة، مع تعليق وتصحيح/نموذج إجابة، ثم يطلق النتيجة صراحةً.
- معاينة الورقة A4: **بدّل بين القوالب مباشرة داخل المعاينة** لترى الشكل المناسب قبل الطباعة أو التصدير إلى PDF، مع مفاتيح إظهار/إخفاء الزخارف ووضع **«صفحتان فقط (ضغط)»** الذي يضغط الأسئلة دون تشويهها في صفحتين.
- تسعة قوالب احترافية للورقة **بخط واحد موحّد وواضح** (خط قالب «النقاء الأنيق»: Noto Kufi Arabic) في كل القوالب — الخطوط المزخرفة الأخرى أُلغيت من الورقة لأنها غير عملية وغير واضحة للطلاب، والخط نفسه يُحمَّل في إطار الطباعة والتصدير فتخرج الورقة والمعاينة والـPDF بالشكل ذاته، وبراويز للصفحة والسؤال، وزخارف علمية متنوعة (34 رمزاً) لا تغطي الأسئلة — مع تحكّم كامل في**حجم الزخارف** و**كثافتها** (خفيف/متوسط/كثيف) و**شفافيتها** (أربع درجات) من المحرّر ومن المعاينة، والزخارف خلف النص دائماً (z-index صفري) فلا تغطي أي سؤال، وتُحفظ الإعدادات مع الاختبار (الوزاري الكلاسيكي، المختبر العلمي، عالم الحياة، الطاقة والكون، المستكشف الصغير، الديواني الفاخر، الرقّي العريق، الأصالة الهادئة، النقاء الأنيق).
- مراجعة جاهزية الاختبار الإلكتروني قبل النشر.
- **بطاقات الاختبارات في لوحة التحكم موحّدة الارتفاع**: المحتوى متفاوت الطول يُقتطع بأسطر محدودة وتُدفع الأزرار إلى أسفل البطاقة، فتصطف البطاقات في صفوف منتظمة دون إخفاء أي تفصيل.

### 💻 الاختبارات الإلكترونية — من يستطيع فتحها؟
من **الاختبارات ← لوحة تحكم الاختبار** (أو من نموذج إنشاء/تعديل الاختبار) تختار:

- **للأعضاء المسجلين فقط** (الافتراضي):
  - يظهر الاختبار للطالب في بوابته **حسب صفه** (ومجموعاته المستهدفة إن حدّدتها — اتركها فارغة ليظهر لكل مجموعات الصف)
  - عند البدء **تظهر بيانات الطالب تلقائياً** من حسابه (الاسم + الصف + المجموعة) ولا يملأ أي بيانات — يجيب عن الأسئلة فقط
  - غير المسجَّل يرى بوابة تسجيل الدخول/إنشاء حساب، ويعود للاختبار تلقائياً بعد الدخول
  - درجته تُربط بحسابه وتظهر في تقريره

- **مفتوح لأي أحد بدون تسجيل**:
  - يظهر في **لوحة الإعلانات** (الصفحة الرئيسية) مع شارة «بدون تسجيل»، ويمكنك أيضاً **نسخ رابطه** ونشره مباشرة
  - الزائر يُدخل **اسمه ورقم هاتفه** (إجباريان)، و**الصف ثابت** من إعداد الاختبار (محدد مسبقاً — لا يستطيع تغييره)
  - يختار **مجموعته من قائمة منسدلة** تعرض مجموعات صفه المتاحة لهذا الاختبار فقط
  - بعد تعبئة بياناته يُفتح له زر «بدء الاختبار»
  - محاولته تصلك في **نتائج الاختبار** باسمه ورقم هاتفه ومجموعته مع شارة «زائر — بلا حساب»
  - الطالب المسجَّل الدخول الذي يفتح اختباراً مفتوحاً للجميع لا يُطلب منه شيء: هويته تلقائية كالأعضاء

> إعدادات مشتركة للوضعين: النشر/الإخفاء، الإتاحة (دائماً/فترة محددة)، حد المحاولات، الأعضاء أو الجميع، مدة اختبار بعدّاد مُلزِم من الخادم وإرسال تلقائي عند انتهائه، وإظهار الإجابة الصحيحة (بعد كل سؤال/في النهاية/أبداً).
>
> في الأسئلة المقالية لا تظهر درجة المقال أو تعليق المعلم أو التصحيح قبل المراجعة اليدوية **وإطلاق النتيجة** للمحاولة.

### 📢 الإعلانات ولوحة الشرف (الصفحة الرئيسية)
- الصفحة الرئيسية للموقع أصبحت عامة وتعرض: الإعلانات، لوحة الشرف، ملفات للتحميل، وروابط مهمة
- تسجيل الدخول أصبح من صفحة `/login` (زر "تسجيل الدخول" في أعلى الصفحة الرئيسية)
- **الإعلانات**: إعلانات مهمة مع إمكانية التثبيت في الأعلى
- **لوحة الشرف**: تثبيت اسم طالب (أو أكثر) في مجموعته لمدة شهر كـ"المتميز في الامتحان هذا الشهر"
- **ملفات للتحميل**: رفع ملفات (حتى 2 ميجا) أو روابط خارجية
- **روابط مهمة**: روابط للطلاب تظهر على الصفحة الرئيسية
- **أزرار الصفحة الرئيسية (تسجيل طالب جديد / دخول الطالب / دخول المعلم)** تظهر كلها على الجوال في شبكة من ثلاثة أعمدة — لا يختفي أي زر على الشاشات الصغيرة (320px فأكثر)

### 📋 الاستبيانات (رأي الطلاب)
- من **الإعلانات ← الاستبيانات** ينشئ المعلم استبياناً ويوجّهه إلى: **الجميع** أو **صف محدد** أو **مجموعات محددة**
- خمسة أنواع أسئلة: اختيار واحد، اختيار متعدد، تقييم (1–5 أو 1–10)، نعم/لا، وإجابة نصية — مع ترتيب الأسئلة وتحديد الأسئلة الإجبارية
- إعدادات النشر: مسودة/منشور، **آخر موعد للإجابة**، **إجابات مجهولة** (لا يُسجَّل اسم الطالب)، و**فتح الاستبيان للزوار** في الصفحة الرئيسية
- الطالب يجيب من حسابه في قسم **«الاستبيانات»**، والزائر يجيب من لوحة الإعلانات الرئيسية **باسمه ورقم هاتفه** (بلا تسجيل دخول) — وإن كان رقمه مسجلاً تُربط إجابته بحسابه وتظهر له استبيانات صفه ومجموعته
- **النتائج فوراً** في لوحة المعلم: أعمدة نسب لكل خيار، متوسط التقييم، قائمة الإجابات النصية، أسماء من أجابوا، و**تصدير CSV**
- الرد الواحد لكل طالب/رقم في كل استبيان (يمنعه فهرس فريد في قاعدة البيانات)، ويمكن للطالب تعديل إجابته ما دام الاستبيان مفتوحاً

### ☁️ التخزين: Supabase فقط — صفر تخزين محلي
- **Supabase هو المكان الوحيد الذي تُسجَّل فيه البيانات**: الطلاب، الصفوف، المجموعات، المواعيد والحصص،
  الحضور، الاستحقاقات والمدفوعات، الاختبارات ومحاولاتها ونتائجها، الإعلانات، لوحة الشرف، الملفات
  والروابط، الاستفسارات، طلبات التسجيل والنقل، سجل الطالب، أرشيف السنوات، والإعدادات كلها.
- **الجلب تلقائي من السحابة**: كل صفحة تجلب بياناتها من Supabase عند فتحها، ولوحة التحكم تسحب كل
  الجداول (`pullAllData`) قبل أن تعرض أي شيء — فتجد بياناتك محدَّثة دائماً.
- **من أي جهاز وأي مكان في العالم**: الطالب يفتح اختباره أو حسابه، وصاحب الموقع يفتح لوحته،
  فيجدان نفس البيانات المحدَّثة — لأنه لا توجد نسخة محلية على أي جهاز.
- **لا يُكتب أي بيان في المتصفح إطلاقاً** (لا `localStorage` ولا `sessionStorage` ولا `IndexedDB`).
  أثناء التصفّح تعمل ذاكرة جلسة مؤقتة (داخل التبويب) تُعبَّأ من Supabase وتُمسح عند تحديث الصفحة
  أو إغلاقها أو تسجيل الخروج.
- **أي كاش قديم تركته إصدارات سابقة في المتصفح** يُنقل تلقائياً إلى الذاكرة (ليرفع إلى السحابة إن
  كانت فارغة) ثم **يُمسح من الجهاز نهائياً** عند أول إقلاع.
- ما يبقى على الجهاز وليس بيانات إطلاقاً: كوكي جلسة دخول الطالب (30 يوماً: بريد + معرف الطالب + الاسم + سرّ جلسة عشوائي، بلا كلمة مرور، ويُمسح عند الخروج)،
  وكوكي قدرة نتيجة اختبار عشوائية (90 يوماً: معرف جلسة وسر فقط، بلا إجابات أو أسماء أو درجات، ويُمسح عند الخروج)،
  ومظهر الموقع (ليلي/نهاري)، وعدّاد حماية الإغراق (أرقام فقط — يمنع تكرار طلبات التسجيل).
- بدون ضبط متغيرات Supabase لا يُحفظ أي بيان: تظهر رسالة «غير متصل بـ Supabase — لا يُحفظ أي بيان».
- **الحارس الآلي**: `scripts/cloud-only-audit.mjs` يفحص كل `src` ويُفشل الالتزام إذا ظهر أي تخزين
  محلي للبيانات من جديد (20/20 فحصاً داخل `npm run verify`).

## 🚀 الإعداد والتشغيل

### المتطلبات الأساسية

- Node.js 22 أو أحدث
- npm أو yarn
- حساب Supabase (مجاني)
- حساب Vercel (مجاني)

### 1️⃣ تثبيت المكتبات

```bash
npm install
```

### 2️⃣ إعداد Supabase

راجع ملف [SUPABASE_SETUP.md](./SUPABASE_SETUP.md) للتعليمات الكاملة.

**ملخص سريع:**

1. أنشئ مشروع Supabase جديد
2. أنشئ حساب مستخدم في Authentication
3. شغّل ملف `supabase/schema.sql` في SQL Editor
4. انسخ مفاتيح API

### 3️⃣ إعداد المتغيرات البيئية

أنشئ ملف `.env.local` في جذر المشروع:

```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

### 4️⃣ التشغيل المحلي

```bash
npm run dev
```

افتح [http://localhost:3000](http://localhost:3000)

### 5️⃣ النشر على Vercel

1. ارفع الكود إلى GitHub
2. اذهب إلى [vercel.com](https://vercel.com) وسجّل الدخول بحساب GitHub
3. اضغط **Add New → Project** واختر repository الخاص بك
4. Vercel يتعرّف على المشروع تلقائياً (Next.js):
   - **Framework Preset**: Next.js
   - **Build Command**: `npm run build`
   - **Output Directory**: `.next` (الافتراضي)
5. قبل الضغط على Deploy، افتح **Environment Variables** وأضف:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGc...
```

6. اضغط **Deploy**

بعد أول deploy، كل push على الفرع الرئيسي ينشر تلقائياً، وكل Pull Request يحصل على رابط معاينة (Preview).

راجع [vercel.json](./vercel.json) للإعدادات (إطار العمل وأوامر البناء وترويسات الأمان).

> **ملاحظة**: المشروع لم يعد يستخدم Netlify — تم حذف `netlify.toml` وإزالة حزمة `@netlify/plugin-nextjs`.

  - فقط المستخدمون المصادق عليهم يمكنهم الوصول
  
- **HTTPS**
  - Vercel يوفر HTTPS تلقائياً
  - جميع الاتصالات مشفرة

- **Environment Variables**
  - المفاتيح ليست في Git
  - محمية في Vercel Dashboard

## 📖 الاستخدام

### الصفحة الرئيسية وتسجيل الدخول

الصفحة الرئيسية `/` هي لوحة الإعلانات ولوحة الشرف العامة (لا تحتاج تسجيل دخول).
للوصول إلى لوحة التحكم اضغط زر «دخول المعلم» الهادئ (أيقونة مفتاح صغيرة بجوار زر «دخول الطالب»
في أعلى يسار الصفحة) وستنتقل إلى `/login`
(استخدم البريد الإلكتروني وكلمة المرور اللذين أنشأتهما في Supabase).

### إضافة البيانات

1. **الصفوف**: أضف الصفوف والمجموعات مع الجداول
2. **الطلاب**: سجل الطلاب واربطهم بالمجموعات
3. **التحصيل**: أنشئ استحقاقات وسجل المدفوعات
4. **الاختبارات**: أنشئ اختبارات وصدّرها PDF
5. **الحضور**: سجل الحضور اليومي

### النسخ الاحتياطي

اذهب إلى **الإعدادات** → **تصدير البيانات** لحفظ نسخة احتياطية.
